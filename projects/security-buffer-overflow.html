Cybersecurity / Academic project 10

Studying buffer overflows and memory protections

Stack-layout reasoning and a controlled SEED buffer-overflow exercise.

Memory safetyASLRStack layoutSEED lab

What I did

Analyzed stack layouts, discussed ASLR and other memory protections, and documented a buffer-overflow exercise with the supplied exploit script in the course lab environment.

Lab setup

The lab used the SEED buffer-overflow environment with vulnerable server containers. I compiled the supplied server and stack programs, started the Docker Compose environment, and verified the running containers and connection to the Level-1 server. Separate 32-bit and 64-bit shellcode test programs supported the exercises, while ASLR settings were varied to observe changes in memory addresses. The downloadable folder preserves the supplied source, Docker configuration and saved lab build files.

Why it matters

Relating unsafe memory copying to stack contents helps explain how overflow vulnerabilities arise and why memory protections matter.

What came out of it

Produced a lab report and exploit source documenting the exercise, parameters and observed behavior.

The exploit retains the supplied SEED lab shellcode and scaffold; the project is presented as course lab work.
